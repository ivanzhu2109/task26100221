# DataForge 增量 SimHash 去重索引

Go 库，包路径 `dataforge/simhash`。输入为上游算好的 `(id uint64, fingerprint uint64)`，
按汉明距离 ≤3 的连通分量实时分簇，簇代表恒为簇内最小 id。单线程使用，无持久化。

## 用法

```go
idx := simhash.New()
idx.Add(id, fingerprint)        // 返回时本次插入引起的簇合并已全部生效
rep, ok := idx.Lookup(id)       // 当前所属簇的代表（最小 id），非插入时缓存值
groups := idx.Groups()          // 全部簇；每条记录恰好出现一次
```

## 实现要点

- **候选索引**：把 64 个比特位按 `位号 mod 4` 交错分成 4 个 16 位带。距离 ≤3 的
  两个指纹至少有一个带完全相同（鸽巢原理），因此只需在 4 个哈希表中查同带记录，
  再做精确距离判定。交错分带使“高 32 位相同”这类分布不会在单个带上整体碰撞。
- **不限制候选为代表**：带表索引的是每条（不同指纹的）记录本身，非代表成员
  产生的连接同样生效；候选不做抽样、不设上限，判定精确。
- **重复指纹 O(1)**：同一指纹只由首个携带者进入带表，后续重复记录仅做一次
  并查集合并，距离计算次数与重复数量无关。
- **并查集**：按秩合并 + 路径压缩，根节点维护簇内最小 id，`Lookup` 近似 O(1)。

## 测试

```sh
go test ./simhash/                              # 全部测试
go test ./simhash/ -run TestSpecifiedSequence   # 题目给定的四记录场景
go test ./simhash/ -run TestAgainstReference    # 与穷举参考实现逐次 Add 核对
go test ./simhash/ -run TestLargeScale -v       # 大规模容量测试（固定种子 42）
```

覆盖内容：指定序列（第三次插入后两簇、第四次经非代表成员合并、代表为 5）、
24 种插入顺序等价性、距离恰为 3 与 4、最高位差异、重复指纹、多跳大簇，
以及每次 Add 后与穷举参考实现的完整分组比对。

## 容量测试结果（本机，Apple Silicon，Go 1.27）

20 万均匀分布不同指纹 + 10 万高 32 位相同指纹 + 10 万复用同一指纹的记录，
打乱后逐条 Add：

- Add 阶段总耗时：约 0.53 s（预算 60 s）
- 峰值堆内存：约 90 MiB（预算 256 MiB）
- 校验通过：40 万个 id 各出现一次、每簇代表为最小 id、重复指纹记录同簇
